# Contributing

Repository-specific contribution instructions and licenses take precedence over these shared defaults. A public repository does not grant rights beyond its own license or publication-rights notice. No organization-wide license is created here.

Useful contributions include package bug reports, minimal examples using non-proprietary material, documentation corrections and evidence-backed research corrections. Describe one concrete problem and link the affected version, page or publication. For research, follow [the research archive guidance](https://github.com/AION-Analytics-India/aion-research/blob/main/CONTRIBUTING.md) and preserve existing citations, limitations and negative results.

Before a substantial change, discuss its scope with the repository maintainer. Follow its tests, supported versions and documented architecture. Do not submit proprietary model implementations, confidential datasets, credentials or third-party material you are not entitled to contribute. Calendar data changes follow the [shared calendar-data maintenance contract](https://github.com/AION-Analytics-India/aion-market-calendar-data); ordinary published data refreshes are separate from package-code releases.

Use issues for public defects and corrections, [customer support](https://aionanalytics.in/contact) for account matters, and the affected repository's published security policy where available for vulnerabilities. Never disclose vulnerabilities or credentials in public issues or Discussions. Avoid promotional issues and unrelated pull requests.
